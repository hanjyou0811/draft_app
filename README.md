# Draft Room

**[ブラウザで遊ぶ](https://draft.ma-kun.fans/)** — インストール不要で利用できます。

招待URLを共有し、複数の参加者が同時に選手を指名できる日本語Webアプリです。指名が重なるとサーバーが抽選し、外れた参加者だけが再指名します。途中経過と完成したチームは、ローカル実行ではSQLite、VercelではSupabaseに保存されます。

Vercelへの公開手順は [Vercel + Supabaseへのデプロイ](docs/deployment/vercel-supabase.md) を参照してください。画面の同期は1秒間隔のAPI取得を使います。

## 必要な環境

- Node.js 22.22 以降
- npm
- Chromium（E2Eテストを実行する場合）

```sh
npm ci
npx playwright install --with-deps chromium
```

## ローカルで試す

```sh
npm run dev
```

ブラウザで `http://localhost:5173` を開きます。このコマンドはViteとAPIサーバーを同時に起動し、終了時には両方を停止します。

1. 作成者が表示名、候補（1行に1人）、各チームの獲得人数を入力して会議を作ります。
2. 待機室の招待URLを参加者へ送ります。
3. 参加者が揃ったら作成者が開始します。
4. 各参加者が候補を選び、指名を確定します。

同じブラウザで招待URLを開くと、保存済みの作成者情報で復帰します。1台のPCで2人分を試すときは、別のブラウザープロファイルまたはシークレットウィンドウを使ってください。

## 本番用ビルドと起動

```sh
npm run build
npm start
```

APIサーバーがビルド済み画面も配信します。既定値は `http://0.0.0.0:3001` です。

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `PORT` | `3001` | HTTP/WebSocketポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス |
| `DATABASE_PATH` | `data/draft-room.sqlite` | SQLiteファイル |

`DATABASE_PATH` には再起動後も残るディスクを指定してください。コンテナへ配置する場合、`data/` または指定先を永続ボリュームにします。バックアップはサーバーを停止した状態でSQLiteファイルを複製してください。

## テスト

```sh
npm test
npm run typecheck
npm run build
npm run test:e2e
```

`test:e2e` はテスト用のViteとAPIサーバーを自動起動し、独立したブラウザーコンテキストで作成、参加、重複指名、抽選、再指名、完成、再読み込み、切断復帰、390px表示を検証します。

## 初版の制約

- 参加者は2〜20人、表示名は1〜30文字です。
- 候補は1〜500人、候補名は1〜100文字、各チームの獲得人数は1〜50人です。
- 開始には `参加人数 × 獲得人数` 以上の候補が必要です。
- 開始後は新しい参加者を追加できません。
- 未提出の参加者がオフラインになると、その人が戻るまで進行は待機します。初版には自動指名、参加者の除外、別端末への参加情報移行はありません。戻れない場合は新しい会議を作成します。
- 参加情報は会議ごとにブラウザーのlocalStorageへ保存されます。招待URLには認証トークンを含めません。

ブラウザー設定でlocalStorageを使えない場合、会議の作成・参加は送信前に停止します。送信直後に保存容量などの理由で保存だけが失敗した場合は、発行済みの参加情報を開いているタブ内で保持し、再読み込みやタブを閉じる前に警告します。

通信が切れた画面では操作を停止し、再接続時に保存済みの最新状態を取得します。操作の応答だけが失われた場合は、サーバーで受付済みの可能性があるため、状態を再取得してから次の操作を有効にします。

## 変更する場所

| 変更内容 | 主なモジュール |
|---|---|
| 指名、抽選、進行ルール | `domain/draft.ts` と `domain/draft.test.ts` |
| 永続化方式や外部DB | `server/repository.ts` を境界に新しいアダプターを追加 |
| HTTP API | `server/http.ts`、認証と直列化は `server/service.ts` |
| ライブ通知 | `server/websocket.ts` と `src/useRoom.ts` |
| ブラウザー通信、参加情報 | `src/api.ts` |
| 画面構成 | `src/components/`、見た目は `src/styles.css` |
| ブラウザーシナリオ | `e2e/draft.spec.ts` |

ドメイン層はReact、HTTP、WebSocket、SQLiteに依存しません。保存処理は非同期の `RoomRepository` を通すため、ルールを保ったまま保存先を交換できます。詳しい境界は `docs/architecture/change-guide.md` にあります。
