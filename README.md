# Draft Room

**[ブラウザで遊ぶ](https://draft.ma-kun.fans/)** — インストール不要で利用できます。

招待URLを共有し、複数の参加者が同時に選手を指名できる日本語Webアプリです。指名が重なるとサーバーが抽選し、外れた参加者だけが再指名します。途中経過と完成したチームは、ローカル実行ではSQLite、VercelではSupabaseに保存されます。

Vercelへの公開手順は [Vercel + Supabaseへのデプロイ](docs/deployment/vercel-supabase.md) を参照してください。画面の同期は1秒間隔のAPI取得を使います。

## 必要な環境

- Node.js 22.22 以降
- npm
- Chromium（E2Eテストを実行する場合）

```sh
npm ci
npx playwright install --with-deps chromium
```

## ローカルで試す

```sh
npm run dev
```

ブラウザで `http://localhost:5173` を開きます。このコマンドはViteとAPIサーバーを同時に起動し、終了時には両方を停止します。

1. 「お題作成」でお題名と候補（1行に1つ）を入力し、公開設定を選んで保存します。初期値は非公開です。
2. 「ルーム作成」で保存済みのお題を選び、表示名と各チームの獲得人数を入力して会議を作ります。
3. 主催者が待機室の「招待URL」タブを開き、専用の招待リンクを参加者へ送ります。
4. 参加者が揃ったら作成者が開始します。
5. 各参加者が候補を選び、指名を確定します。

「お題作成」の「公開のお題からコピー」から、公開済みのお題の候補を取り込めます。コピー元を選んで「候補をコピー」を押すと候補欄が置き換わり、保存前に自由に編集できます。入力済みのお題名はそのまま残ります。別のお題として保存され、コピー元は変更されません。公開設定はコピー元から引き継がず、初期値は非公開です。

公開のお題は全員が選べます。非公開のお題は作成したブラウザだけが選べます。ログインは不要で、ブラウザに保存する作成者トークンをサーバーで確認します。ブラウザの保存データを削除したり、別のブラウザを使ったりすると、非公開のお題を選べません。非公開のお題から作った会議では、招待された参加者にお題と候補が表示されます。

お題はルームと別にデータベースへ保存され、同じお題で何度でもルームを作成できます。ルームにはお題と候補のコピーを持たせるため、他のルームの指名結果は影響しません。

参加済みのブラウザでは、保存済みの参加情報を使ってルームURLから復帰できます。1台のPCで2人分を試すときは、別のブラウザープロファイルまたはシークレットウィンドウを使ってください。

## 本番用ビルドと起動

```sh
npm run build
npm start
```

APIサーバーがビルド済み画面も配信します。既定値は `http://0.0.0.0:3001` です。

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `PORT` | `3001` | HTTP/WebSocketポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス |
| `DATABASE_PATH` | `data/draft-room.sqlite` | SQLiteファイル |

`DATABASE_PATH` には再起動後も残るディスクを指定してください。コンテナへ配置する場合、`data/` または指定先を永続ボリュームにします。バックアップはサーバーを停止した状態でSQLiteファイルを複製してください。

## テスト

```sh
npm test
npm run typecheck
npm run build
npm run test:e2e
```

`test:e2e` はテスト用のViteとAPIサーバーを自動起動し、独立したブラウザーコンテキストで作成、参加、重複指名、抽選、再指名、完成、再読み込み、切断復帰、390px表示を検証します。

## CI

GitHub Actionsで、PRの作成・更新時と `main` へのpush時に、Node.js 22でテスト、型チェック、ビルド、ChromiumのE2Eテストを実行します。Actions画面から手動実行もできます。追加のSecret設定は不要です。

E2Eテストは失敗時に1回再試行し、`test.only` が残っている場合は失敗します。失敗時のスクリーンショットとトレースは、Actionsの実行詳細から `playwright-test-results` をダウンロードして確認できます（7日間保存）。

マージ前にCIの成功を必須にする場合は、GitHubのブランチルールで `main` に対する必須ステータスチェックに `Test, typecheck, build and E2E` を指定してください。

## 初版の制約

- 参加者は2〜20人、表示名は1〜30文字です。
- 候補は1〜500人、候補名は1〜100文字、各チームの獲得人数は1〜50人です。
- 開始には `参加人数 × 獲得人数` 以上の候補が必要です。
- 開始後は新しい参加者を追加できません。
- 未提出の参加者がオフラインになると、その人が戻るまで進行は待機します。初版には自動指名、参加者の除外、別端末への参加情報移行はありません。戻れない場合は新しい会議を作成します。
- 参加情報は会議ごとにブラウザーのlocalStorageへ保存されます。ルームURLには参加権限を含めません。招待URLには新規参加専用のキーが含まれますが、参加者自身の認証トークンは含めません。

ブラウザー設定でlocalStorageを使えない場合、会議の作成・参加は送信前に停止します。送信直後に保存容量などの理由で保存だけが失敗した場合は、発行済みの参加情報を開いているタブ内で保持し、再読み込みやタブを閉じる前に警告します。

通信が切れた画面では操作を停止し、再接続時に保存済みの最新状態を取得します。操作の応答だけが失われた場合は、サーバーで受付済みの可能性があるため、状態を再取得してから次の操作を有効にします。

## 変更する場所

| 変更内容 | 主なモジュール |
|---|---|
| 指名、抽選、進行ルール | `domain/draft.ts` と `domain/draft.test.ts` |
| 永続化方式や外部DB | `server/repository.ts` を境界に新しいアダプターを追加 |
| HTTP API | `server/http.ts`、認証と直列化は `server/service.ts` |
| ライブ通知 | `server/websocket.ts` と `src/useRoom.ts` |
| ブラウザー通信、参加情報 | `src/api.ts` |
| 画面構成 | `src/components/`、見た目は `src/styles.css` |
| ブラウザーシナリオ | `e2e/draft.spec.ts` |

ドメイン層はReact、HTTP、WebSocket、SQLiteに依存しません。保存処理は非同期の `RoomRepository` を通すため、ルールを保ったまま保存先を交換できます。詳しい境界は `docs/architecture/change-guide.md` にあります。

## お題API

- `POST /api/topics`: `{ title, names, isPublic? }` を保存。`names` は改行区切り、`isPublic` の省略時は非公開。
- `GET /api/topics`: 公開のお題と、呼び出した作成者自身の非公開のお題を取得。
- `POST /api/rooms`: `{ name, topicId, teamSize }` で保存済みのお題から会議を作成。

お題の作成者は `x-topic-owner` ヘッダーで識別します。トークンは2つのUUID v4を連結した文字列で、保存時にはSHA-256ハッシュに変換し、一覧やルームに含めません。非公開のお題を他の作成者が指定した場合は404を返します。

SQLiteは起動時にお題用テーブルを自動追加します。既存ルームは引き続き利用できます。Vercel/Supabaseでは `supabase/migrations/20261110000000_saved_topics.sql` をAPIの更新前に適用してください。旧形式のルーム作成APIも既存クライアント向けに維持しています。

## ルーム画面

待機中は「参加者」「候補リスト」「招待URL」のタブを切り替えます。初期表示は参加者で、招待URLはそのタブを開いたときだけ表示します。開始ボタンと必要な候補数は常に表示し、多数の参加者・候補は一覧の中でスクロールできます。

開始後は巡を行、参加者を列にした表で獲得結果を確認します。候補を検索して選び、「指名を確定」を押します。まだ結果が出ていない他の参加者の指名内容は表示しません。表と候補欄を個別にスクロールでき、履歴は「履歴を見る」から開けます。通常時は接続表示を出さず、接続が切れた場合に「再接続中」を表示して操作を停止します。

スマートフォンでは結果表の下に候補選択を配置します。参加者が多い場合は表を横にスクロールして確認できます。横向き・拡大表示などで画面の高さが非常に小さい場合は、操作を隠さないためページスクロールも利用できます。

## 招待リンクと配信時のURL

- `/room/:roomId` は参加済みブラウザ用です。ルームIDだけを知っていても、新しく参加できません。
- `/invite/:inviteKey` は新規参加用です。主催者の「招待URL」タブで管理できます。タブを開いても初期表示はアスタリスクで、「表示する」を押したときだけURLが表示されます。「URLをコピー」は非表示のまま使えます。タブを開き直したときや再発行・再読み込み時は非表示に戻ります。参加が完了すると `replaceState` で招待キーを含まないルームURLへ移動します。
- 主催者は待機中に「招待リンクを再発行」で以前のリンクを無効にできます。参加済みの認証情報には影響しません。再発行の結果が不明な場合は古いリンクを表示せず、最新リンクを読み直します。
- 招待URLも配信に映れば、そのリンクを知った人は参加できます。通常は参加者タブを表示し、共有が必要なときだけ招待URLタブを開いてください。

招待リンクを知っているだけでは、主催者操作や参加済みの他人としてのアクセスはできません。招待用キーは参加者トークンから用途を分け、ルームの通常レスポンスには含めません。DBにはランダムなnonceとキーのハッシュだけを保存し、認証済み主催者が表示するときにHMACで再構成します。既存ルームでは主催者が招待タブを開くと招待情報が追加されます。既存の参加者はそのまま復帰できますが、従来のルームURLだけでの新規参加はできなくなります。

招待API: `GET /api/rooms/:id/invitation`（表示）、同URLへの`POST`（再発行）は主催者Bearer認証が必要です。`POST /api/invitations/resolve` と `POST /api/invitations/join` は本文で `inviteKey` を受け取ります。旧 `POST /api/rooms/:id/join` も本文の `inviteKey` が必須で、旧 `GET /api/rooms/:id/info` は `x-invite-key` ヘッダーを必須にしています。
