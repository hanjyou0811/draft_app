# Vercel + Supabase移行設計

目的は既存の会議作成・参加・指名・抽選・復帰をVercelで公開すること。専用Supabaseプロジェクトは `bcvanvhqvodibxfeufqk`。

- Viteの画面を配信し、`api/index.ts` が既存HTTPルートを受け持つ。
- `RoomRepository` のSupabase RESTアダプターを追加する。JSONB集約、保存形式番号、更新番号を保持する。
- DBの更新番号を条件に保存し、競合時は最新集約から最大24回再試行する。公開ビューの生成と通知は保存成功後にのみ行う。
- ブラウザへの未公開指名・認証ハッシュ流出を防ぐため、DBの直接アクセスを閉じる。サーバー専用キーを環境変数に設定する。
- 同期は1秒間隔の認証付きHTTP取得とする。Supabase Realtimeは参加者別認証との追加統合が必要なため今回は導入しない。WebSocketをVercelへ移す案も複数インスタンスの通知共有が必要なため採らない。
- 通信失敗中は操作不可。再取得に成功すると復帰し、古い更新番号の画面を適用しない。完成後は定期取得を終了する。
- ローカルSQLite環境と既存のWebSocketサーバーは互換性のため維持する。未コミットの画面変更は保全する。

検証は独立サービス間の同時操作、REST保存の競合判定、Vercelの転送パスと解析済みJSON、既存ルール/APIテスト、型検査、ビルド、複数ブラウザのE2E。実SupabaseとVercelの検証にはユーザー側のSQL適用と認証設定が必要。
